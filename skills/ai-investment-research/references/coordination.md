# 模块协作与不冲突约定

## 一份合同、一个主报告

主研究者拥有研究边界、共享事实、公司主估值版本和综合报告。模块执行者只修改分配的相对目录，返回产物路径、核心判断ID、来源ID、重要分歧和缺口，不把全部原文塞进主上下文。

从完整研究中可并行的部分：行业结构与公司披露采集、已明确事件的专题、独立技术图分析、宏观背景。需要行业/经营分类后才能合理选择的估值方法保留依赖顺序。没有目标事件时不为了凑模块捏造事件；没有指定公司时不擅自把行业前五家公司全部展开成昂贵全套深研，可按边界选择重点并说明。

## 子任务说明建议

每条子任务传入：

```text
本题使用 ai-investment-research 的 [模块] 方法。
只读取对应 references/[模块].md 和必要上游资源。
运行目录：[ABS_RUN_DIR]；可写目录：[本模块相对路径]。
研究对象/市场/截止日/币种/财年/期限：[从research.json复制]。
共享资料：[来源/文件路径]；需要回答：[本模块问题]。
交付：[模块.md + 新来源/主张/预测建议]；不得改其他模块和总报告。
不编数据；资料/工具不足写limited及影响，不请求用户重复已确认的范围。
```

子任务新增来源暂存本模块 `evidence-additions.json` 等；主研究者分配稳定ID并合并到三份总台账。真正的子代理独立完成才能标独立复核；同一代理分角色思考写自审。若宿主仅单代理，按模块分阶段执行，保持事实/观点独立，不声称并发或第二意见已完成。

## 需要对账的冲突

| 问题 | 处理 |
| --- | --- |
| 同一公司收入不同 | 对报告期、币种/单位、合并范围、重述/累计/单季，再决定主数据或并列缺口 |
| 行业估值与公司DCF不同 | 行业倍数是背景；具体公司主模型保持唯一，解释方法/假设差异，不悄悄改目标 |
| 技术偏弱但长期低估 | 以方法和期限分列，可同时成立；主报告解释催化与证伪，不强行一票否决全部 |
| 宏观与事件观点相反 | 写条件、时滞和受益环节；检查事件是否已被宏观指标反映，避免重复计入 |
| 两个模块情景概率不同 | 若是不同事件/条件就不相加；若同一事件，主研究者按同一假设树解释并留修订记录 |
| 大陆/香港/美国同名标的 | 用市场＋代码唯一标识，汇率和ADR换算逐步披露 |

## 进度与恢复

- 以 `research.json` 的模块状态、简报和已有真实文件恢复，不依赖上次对话记忆。
- 简单任务不引入不必要阶段确认。用户改变范围时更新合同、解释影响，保留已完成但不再适用的资料。
- 每个模型/模块产物标 `as_of` 与版本。更新使用新run或新版本，不覆盖之前的报告和已注册预测；使用上一版状态时先核查新披露与截止日。
- 网络/数据商失败可换公开权威源；缺少同等数据则降级，不能将摘要来源变成已深读原文。
