# 系统逻辑与状态流

[中文 README](../../README.zh-CN.md) · [文档索引](../index.md) · [English](../en/system-logic.md)

系统把研究判断和出版分成两个可核对的环节：研究者负责事实与模型，发布器负责已定稿内容的排版与审计。
可搬迁包包含五个上游技能、三个上游仓库的固定快照及保留的许可证；整合版为 1.1.0。
具体方法见 [研究方法论](methodology.md)，字段及命令见 [数据契约](data-contracts.md)。

## 1. 一轮研究的主链路

```mermaid
flowchart LR
  A[人类简报] --> B[独立运行目录]
  B --> C[来源与证据]
  C --> D[数据集与主模型]
  D --> E[复核与修正]
  E --> F[报告 content JSON]
  F --> G[离线发布器]
  G --> H[PDF审计与阅读检查]
  H --> I[交付与预测跟踪]
```

图中箭头表示前置条件，不要求每一步由不同代理完成。
发现事实或模型问题时回到对应证据/模型修正，再同步正文并重建出版物。
目录或版面问题回到内容组织与发布配置；发布器不会自动修正研究结论。
交付之后按预测原始日期和条件复盘，更新建立新版本。

## 2. 宿主与 Python 核心的职责

模型宿主读取技能、理解问题、查找和阅读资料、形成判断、写正文并协调复核。
网络可用时由宿主提供搜索/抓取能力；离线时以用户资料和现存材料为边界。
凭据通过宿主安全配置，发布包不捆绑行情商账户、模型密钥或自动登录配置。

[核心脚本](../../skills/ai-investment-research/scripts/research.py) 使用 Python 标准库维护工作区、检查记录并导出基本阅读格式。
`doctor` 检查存在状态；`init` 建目录和空台账；`check` 查结构；`render` 消费已撰写的 Markdown。
这些命令不抓取财报、不调用模型、不生成事实，也不因初始化成功就生成完整研报。
`init --output` 必须显式给出绝对目录；技能的输出偏好是代理使用约定，不是 CLI 自动读取的个人路径。
既有合法运行可以恢复；已有非研究目录被拒绝，历史研究应另建版本。

[独立发布器](../../skills/ai-investment-research/scripts/publisher.py) 读取运行内内容 JSON 和 PNG/JPEG，离线生成 PDF、Markdown、HTML 及审计。
它需要额外的报告依赖和可用字体；核心工具的标准库定位不等于 PDF 零依赖。
安装、离线演示和打包工具属于便携分发环节，不是实时自动研究服务。

## 3. 运行目录是恢复边界

| 位置 | 职责 |
| --- | --- |
| `00_brief/` | 研究简报、范围、假设及缺口 |
| `01_sources/raw/` | 原始证据；其他来源子目录可按运行需要组织 |
| `02_analysis/` | 行业、公司、事件、技术与宏观模块结果 |
| `03_models/` | 标准化数据、主假设、可复算模型及图表 |
| `04_deliverables/` | 实际完成的阅读成品 |
| `99_internal/` | 内容 JSON、复核记录、检查与发布审计 |
| 根层四份 JSON | 运行状态、来源、主张、预测的公共合同 |

存入合同的路径相对于本次运行；内容和图片解析后不得越界，包括符号链接越界。
原始材料不因导出而删除，模型产物不冒充原始披露。
从运行状态、简报和真实文件恢复工作，不能只依赖上次对话记忆。
完成产物需要与当前内容哈希相对应；旧审计不能证明新一轮构建成功。

## 4. 研究状态与出版状态分开

模块在 [运行状态契约](data-contracts.md) 中保持五个固定键，各自带 `status / reason / artifact`。

| 模块状态 | 含义 | 记录要求 |
| --- | --- | --- |
| `pending` | 尚未完成 | 保留待办，不包装为结论 |
| `complete` | 约定范围内已完成 | 指向真实模块产物 |
| `limited` | 缺证据/能力，但有有限结果 | 原因与结论影响写入正文 |
| `skipped` | 本题不适用 | 明确说明不适用原因 |

运行总体状态是 `draft / complete / limited`，不是上述模块状态的另一套拼写。
`full` 表示用户要求的研究范围；适用模块未完成时，不能以“已导出”宣称完整研究。
确实不适用的技术或宏观模块可解释后跳过，不需要用空章节补齐。

| 发布审计状态 | CLI 退出码 | 解释 |
| --- | --- | --- |
| `pass` | 0 | 本次已实现的排版审计通过 |
| `warning` | 0 | 已构建但存在真实警告，需阅读审计并处理或披露 |
| `fail` | 2 | 审计失败，不能作为通过的出版物交付 |
| 输入/构建异常 | 1 | 检查错误说明；既有 manifest 不是本轮成功凭证 |

运行 `limited` 可以拥有排版 `pass`；研究 `complete` 也可能遇到出版 `fail`。
PDF 页数、哈希和版面通过不证明来源真实、模型合理或预测可靠。

## 5. 并行角色与依赖

行业结构、公司披露采集、明确事件、独立技术图分析和宏观背景可以在边界清晰时并行。
估值方法选择依赖业务分类和数据口径，综合结论依赖模块对账，正文依赖主模型冻结。
每个任务给对象、市场、截止日、币种、可写目录、问题、交付与证据回传要求。
模块新增来源先局部暂存，由主研究者合并稳定 ID，避免争抢公共台账。

角色可以是主研究者、数据提取者、模型执行者和独立复核者；不强制采用某一代理框架。
没有子代理时按相同依赖顺序执行并标为自审，不声称获得独立第二意见。
共享事实与主估值只维护一个有效版本，重复转述不增加证据数量。
修正说明须列问题、影响、改动位置和验收状态；只通知“已修改”不等于复验完成。

## 6. 同源出版与实际分页

核心 `render` 从 Markdown 生成 HTML/DOCX，PDF 则按可用浏览器尝试打印。
独立发布器从 content JSON 同时生成 Markdown、独立 HTML 和 PDF；正文、表格、图源与来源共用输入。
两条流程可能写入同名阅读文件，应按最终交付选择流程，并以最后一次构建的审计为准。
独立发布器不接受任意 HTML 作为可执行内容，不联网补图，也不补造引用关系。

输入 `pages` 表示逻辑页，不承诺一项等于一张物理 PDF 页。
封面固定一页，`planned_pages = 1 + len(pages)`；正文过长可以自然延页。
实际页数及每项逻辑页的起止页来自最终 PDF；计划与实际不一致至少产生 `warning`。
长表按行拆分并重复表头；单行或图组无法容纳时明确失败，不把文字挤成不可读尺寸。

可见目录使用 `type: "toc"` 且 `blocks: []`，由发布器按实际起页生成。
目录最多经过六次重排求收敛，失败则报错；正文中手写的目录页码不会被自动修正。
书签和章节起页使用实际映射；Markdown/HTML 中的 PDF 页码也来自该映射。
HTML 将本地图像嵌入 data URI，可复制为单文件离线阅读；图像保留原始字节。

## 7. 交付门槛

确认研究范围和缺口披露、复核修正状态、核心结构检查及出版审计分别有证据。
打开至少一个真实阅读版检查字体、表格、图源、链接与分页，PDF 实际存在才列为成品。
未做视觉检查时明确记录，不把文本框审计或哈希检查描述成视觉验收。
交付关键结论、截止日、主要成品和重要限制，并保留证据及原预测以便追踪。
合成离线演示用于验证软件入口和出版链路，历史研究快照用于说明纠错过程；两者均非实时投资建议。
